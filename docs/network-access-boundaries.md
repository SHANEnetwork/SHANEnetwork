# SHANE access boundaries

SHANE Network participation must not imply ownership of, or access to, private endeavor data.

- Public discovery is separate from joining a group.
- Group membership is separate from workspace collaboration.
- Workspace collaboration is separate from administrator privileges.
- A sponsored subscription enables designated services, not private data access.
- Each endeavor owns its own resources unless joint ownership is expressly established.
- SHON and SHANE remain separate services with separate member data.
- Cross-service identity linking requires consent and independently enforced authorization.
- Server-side policies must validate every private resource operation. Browser controls alone are insufficient.
- Private messages, agreements, locations, files, and AI conversations require specific grants.
- Abuse protection should include rate limits, reporting, blocking, and independent moderation.
- A blocked participant must not be allowed to bypass restrictions using invitations.
- Group access must never automatically authorize editing or publishing an endeavor.
- Access to essential SHON services should not require paid SHANE subscriptions.

Implementation status: design only. No federation or cross-site access is activated by this document.
