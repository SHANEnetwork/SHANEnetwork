# SHANE internal evolution laboratory: development protocol

This is an **internal development method**, not a SHANE member-facing product or a published service. Its browser worksheet lives at `internal-tools/evolution-laboratory.html`. Do not add it to SHANE's menus or SHONnetwork. An unlinked HTML path is not private; never enter secrets or personal data. Run locally if confidentiality matters.

## Whole-first decision cycle
1. **Vision and invariants.** State the full member outcome, existing working features to preserve, account/data boundaries, SHON isolation, and falsifiable acceptance criteria.
2. **Ponderers.** Generate at least two genuinely different complete architectures, including a conservative reuse path. Compare consequences, dependencies, failure modes and user effort, not just feature counts.
3. **Spiral Compass I.** Distinguish evidence, assumptions, missing information and unsupported claims.
4. **Spiral Compass II.** Seek hidden dependencies, triggers, traps, access and migration risks.
5. **Spiral Compass III.** Detect overlap, imbalance, misalignment and contradictory meanings across modules.
6. **Mirror Cat / Compass IV.** Attempt to falsify the leading design with a strong counterexample; turn negative results into specific redesigns or tests.
7. **Fractal Compass.** Check that each operation supports the endeavor, each endeavor supports the Network, and the Network remains coherent at account and deployment scale.
8. **Spiral Tuning Fork.** Compare the meaning of terms such as “created,” “published,” “invited,” “private,” “saved” and “ready” across components. Do not allow UI text to promise an unperformed operation.
9. **Harmonizer.** Preserve complementary strengths, resolve contradictions, and document tradeoffs that cannot be eliminated.
10. **Maximizer.** Choose or synthesize the strongest option using explicit criteria: vision fit, preservation, feasibility, evolutionary potential and verifiability. Weighted scores are hypotheses, not proof.
11. **Genies / Genari.** Research specialized solutions through current documentation, public patent applications and expired patents, obscure technical literature, standards and historical designs. Record actual source links, provenance, rights, limitations, counterevidence and dates. A generated research query is not a completed search.
12. **Pre-commit gate.** Record exact files/DB objects affected, real test evidence, rollback path, permission/privacy review and remaining uncertainty. Do not call the gate passed without actual verification.
13. **Evolution loop.** Compare results with the whole vision after each substantive change; revise the strategy without destroying proven working components.

## Pre-commit evidence record
- Vision and acceptance criteria
- Competing designs and rationale for the chosen synthesis
- Reused programs and capabilities, plus any known gaps
- Security, owner scope, privacy and external side effects
- Data migration and rollback procedure
- Actual tests run, results and failures
- Source evidence, licensing and uncertainty for Genari leads
- Decision: proceed / revise / defer

## Operational boundaries
The worksheet runs deterministic browser-side comparisons, not autonomous AI agents or external research. It cannot run GitHub tests, inspect the database or commit code. The assistant can apply this protocol while inspecting repository files and using available development tools; the worksheet is an optional companion for human review. Preserve existing routes and SHONnetwork, and require explicit authorization before publishing, contacting others, charging or changing access.

## Original architecture lineage
Ponderer → Harmonizer → Harmonizer-Maximizer Loop → Genari/Genies, with recursive reflection, forward/backward outcome review, Double-Harmonizer Trick, Spiral and Fractal Compasses, Mirror Cat, Spiral Tuning Fork, and the principle of turning negative results into productive design information. These are recovered design principles; the historical existence of fully implemented source modules has not been verified. Do not misrepresent newly implemented heuristics as recovered original executable programs.
